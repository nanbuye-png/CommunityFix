# 在线 WebSocket 通知

2026-11-03。管理端（SUPER_ADMIN / ADMIN）及居民、维修工客户端（RESIDENT / WORKER）接入 `/api/notifications/live`。

## 使用效果与权限

- 管理端顶部显示消息未读数，新消息到达时弹出提示，消息列表自动刷新。
- 居民、维修工端显示消息 tab 角标和新消息提示，消息页可自动刷新；应用切到后台主动断开，回到前台重新同步。
- 所有身份只同步当前账号的站内通知，不开放角色广播、客户端自选用户或房间。系统管理员没有默认跨用户收件箱权限，多角色账号使用同一收件箱。
- 本次没有扩大工单、咨询或公告的收件人规则。管理员只会收到原有业务为其创建的消息，不会收到全小区所有通知。
- 推送只包含未读数和最新消息编号，正文与详情仍经现有鉴权 HTTP 接口查询。RabbitMQ 继续负责微信通知投递，WebSocket 不消费微信工作队列。

## 协议与认证

握手路径允许建立尚未认证的 WebSocket，但收到合法认证帧之前不发送消息；默认约 5～8 秒未认证关闭。首帧：

```json
{"type":"auth","token":"当前登录JWT"}
```

JWT 通过消息帧发送，不写入 URL 查询串、Cookie 或日志。浏览器 Origin 按现有 `CORS_ORIGINS` 检查；开发 Vite 同源代理与 HTTP 路径一样移除转发 Origin。正式环境使用 WSS。客户端不能订阅其他用户，也不能通过该连接执行业务写操作。

认证后服务端发送：

```json
{"type":"notifications","latestId":"123","unread":2}
```

每次同步前重新验证 JWT 过期时间、账号启用状态和 token_version；退出登录、改密撤销会话或禁用账号后，现有连接在下一轮检查关闭。业务权限仍由详情接口动态判断。1008 表示认证/协议失效，客户端清理当前登录；1011 表示临时故障，可重连；1013 表示连接容量限制。

单实例最多 1000 条连接，每账号最多 5 条已认证连接（均为实例内限制）。文本帧上限 4 KiB，限制发送缓冲并使用 Spring 并发发送保护。正式容量应结合数据库、反向代理连接限制及压测设置，不将这些固定上限视为容量验收结果。

## 多实例、重连与边界

首版每个后端实例默认每 3 秒扫描自己的在线连接，从共享 MySQL 中读取该用户已提交的通知摘要，并推送快照作为心跳。RabbitMQ 或 Redis 不参与浏览器投递。因此业务写入发生在其他实例也能同步，无需会话粘滞，不存在微信竞争消费导致在线用户漏收的问题；没有活跃连接时不查询收件箱。

这是定时核对驱动的 WebSocket 推送，正常同步间隔约 3 秒，加上扫描与数据库耗时，不承诺毫秒级实时。数据库负载随在线连接增长；当前每连接检查身份和聚合收件箱，后续大量在线用户应另做压测，再考虑 Redis Pub/Sub 唤醒加数据库补偿、分组查询等优化。

客户端 15 秒收不到心跳则重连，退避从约 1 秒增长到最多约 30 秒并带抖动；重连后重新获取最新摘要，消息页通过 HTTP 补查持久化记录。推送快照不是完整事件流，离线期间的逐条事件不依赖 WebSocket 保存；消息列表才是记录依据。消息角标依据已读状态更新，不会自动将消息标为已读。

这属于页面/应用在线通知，不是浏览器系统通知，也不支持页面关闭后的后台推送。微信小程序正式使用需配置 socket 合法域名和 WSS，并做真机前后台切换验收。
