# 报价确认与通知修复（2026-11-04）

## 本次改动

居民消息页的报价通知增加“查看并确认报价”，点击进入对应工单的费用区域，可查看明细并确认或拒绝当前报价。已被替换、已回复或终止工单的旧通知不会重新开放确认。物业端消息增加对应工单入口。

居民与物业的费用面板监听在线通知并重新获取费用状态，不再仅依赖工单版本变化；报价变化没有递增工单版本，因此原有监听会漏掉正在打开的费用面板。异步读取增加序号校验，防止较早响应覆盖最新数据。居民消息页增加连接状态和手动刷新入口。

报价创建在同一事务中写入站内消息、预占微信报价模板授权并建立 outbox；事务回滚时授权与消息一起回滚。同一报价事件只入队一次。无微信身份或无该模板授权时不入队，不影响站内报价确认。微信发送沿用既有 RabbitMQ/outbox 重试链路，金额从整数分转成两位小数元。报价模板与接单模板分别配置，不能相互挪用授权。

```dotenv

WECHAT_QUOTE_ORDER_FIELD=character_string3
WECHAT_QUOTE_AMOUNT_FIELD=amount10
```

还需要已有的 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`。已按用户新提供的模板更换为编号 1022，微信后台标题为“新订单通知”，业务场景为报价待确认。更换后需要用户重新授权新模板，旧模板授权不会转移；已按旧模板建立的待发消息不会自动改用新模板发送。

小程序使用微信登录，在自费报修页或个人中心点击“订阅一次后续报价微信提醒”，用户同意后记录本模板授权。之后物业创建新报价才会尝试投递。授权不会自动补发已经存在的旧报价；旧报价直接在站内确认。H5 使用在线通知，订阅按钮说明应在微信小程序内授权。

本次不发送真实微信消息，不把模拟发送测试称作微信真机投递验收。微信后台模板所属小程序、合法域名、真实用户授权及最终送达仍需真机联调。

## 本地环境修复

Compose 在选择 `mysql` 服务前也会解析整个文件，缺失的 `RABBITMQ_PASSWORD` 会让命令在解析阶段失败，并非 MySQL 容器健康检查失败。

`python deploy/init-dev.py --upgrade` 现在能补齐缺失或空白的 `REDIS_PASSWORD`、`RABBITMQ_PASSWORD`，保留其他配置及已有非空密码。新建 `.env` 也会生成这两个密码；不向终端输出密码。本地配置已补齐，原命令实测成功：

```powershell
docker compose --env-file deploy/.env -f deploy/compose.yml -f deploy/compose.dev.yml up -d mysql
```
