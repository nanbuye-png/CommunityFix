# 报价、账单与模拟支付（第一期）

2026-11-04，按已确认流程实现：物业报价 → 居民确认 → 维修 → 居民验收 → 模拟支付。正式环境未部署，交互验收按用户要求暂缓。

## 范围与使用

新报修可选自有设施或公共设施，物业审核通过即确认归属；审核前可在费用面板更正并留下原因与审计记录。公共设施须填写实际位置，居民无需支付，不创建零元交易。当前仍需选择本小区已绑定房屋作为申报资格凭证，公共位置单独记录；尚未提供无房屋绑定人员的公共报修入口。

新工单默认自有设施，不能通过省略字段绕过报价。历史工单保留 billing_version=0，不补收费用。

物业审核后可在详情费用面板提交完整报价，每项包含名称、数量和单价。金额以人民币分存储，单张总额范围0.01～100000元，最多30个项目。居民只能回复自己工单的报价。物业只能操作授权小区，维修工不能修改报价或支付。系统管理员未获得跨小区账单读取权限。

自有设施必须有已确认报价且没有待确认的新报价，才允许派单、开始、保存维修过程、完工和验收。追加报价是新的完整总价，包含原项目；旧版保留。新报价待确认时暂停相关操作，拒绝后继续沿用此前已确认价格；首次报价被拒绝则继续等待协调报价或取消。

居民验收与账单创建在同一数据库事务内完成。维修 CLOSED 与账单 UNPAID 分别保存，评价和投诉规则维持原有方式。返修发生在验收前，可继续使用原报价；追加费用仍须再次确认。已验收后不能修改报价。

公共设施不出账单；取消或驳回工单不出账单。模拟支付只允许本人在验收完成后操作，金额取账单，不接受客户端金额覆盖。订单锁、账单锁、唯一约束与Idempotency-Key防止重复生成账单和交易。状态明确为 MOCK_PAID / MOCK_SUCCESS，交易号以 MOCK- 开头，不表示真实支付或实际收入。

报价、居民回复、账单和模拟支付事件写入现有站内通知，可由已接入的WebSocket提示。2026-11-04补齐报价确认入口、费用面板在线刷新，以及独立的微信报价订阅模板接入，详见[报价通知修复说明](quote-notification-fix-2026-11-04.md)。RabbitMQ微信投递链路不被用来判定付款成功。

## 配置与API

模拟支付需 `DEMO_ENABLED=true` 且 `BILLING_MOCK_ENABLED=true`。直接后端启动未指定模拟开关时跟随演示模式；主Compose默认显式关闭模拟支付。若非演示模式强行启用则启动失败。`deploy/.env`未自动修改。

统一路径 `/api/repair/orders/{id}/billing`，GET获取费用状态。以下POST均要求Idempotency-Key：

| 子路径 | 内容 |
| --- | --- |
| /scope | facilityScope、locationText、reason；仅物业在审核前更正 |
| /quotes | revision为当前最新版本（首版0）、items[{name,quantity,unitPriceFen}]、reason |
| /decision | quoteId、accepted；仅本单居民回复待确认版本 |
| /payment-attempts | billId；创建或复用本账单有效的模拟支付单 |
| /mock-pay | billId、attemptNo；金额取自账单，同一成功支付单可以安全重试 |

居民点击「去支付」时开始 30 分钟倒计时。GET 费用详情返回数据库时间 `serverTime` 和最近一次 `paymentAttempt`（首次发起前为 null），含支付单号、金额、创建时间、截止时间和状态。刷新页面或更换设备会沿用原截止时间。

从截止时刻起，服务端返回 HTTP 409 和 `PAYMENT_ATTEMPT_EXPIRED`。居民点击「重新支付」并使用新的幂等键，可获得新支付单号。旧客户端只提交账单号会收到 `PAYMENT_ATTEMPT_REQUIRED`，需更新客户端并刷新账单。付款窗口到期后，维修仍为已完成、账单仍为待支付。

V9 迁移新增 `repair_payment_attempt`，每张账单最多一张 PENDING 支付单。确认时按 MySQL 时间在事务锁内校验；后台默认每分钟分批标记 EXPIRED，支付校验独立于扫描进度。付款成功时，同一事务标记 SUCCEEDED、登记模拟交易、更新账单并发送站内通知。已有已付账单无需回填支付单。

V8迁移为工单新增归属、位置与计费版本，并创建repair_quote、repair_bill、repair_payment。迁移未应用到现有演示或正式数据库，仅由隔离测试使用。

## 后续范围

真实微信支付、收款商户、渠道验签与查单、退款、对账、发票及维修工结算尚未实现，也未接入任何真实资金。模拟账单不会自动转换成真实应收款。紧急抢修的收费例外、免收/保修规则与高并发容量需在真实上线前明确。

首期仍在现有Spring Cloud业务后端内独立billing模块实现，尚未拆成单独部署的支付微服务。
